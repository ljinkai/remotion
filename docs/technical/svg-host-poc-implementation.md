# PNG → SVG → 动画技术实现备份

记录日期：2026-10-24。状态：**已完成并验证的隔离 POC**。这份文档独立保存实现原理、复现步骤与验证边界，不依赖聊天记录；本次仅新增文档，没有接入语音或生产视频流程。

配套 OpenSpec：[方案](../../openspec/changes/document-svg-host-poc/proposal.md)、[设计](../../openspec/changes/document-svg-host-poc/design.md)、[需求场景](../../openspec/changes/document-svg-host-poc/specs/svg-host-poc/spec.md)。

## 1. 已验证的路线

```text
唯一原始 PNG（1086 × 1448）
  → 清理透明背景中的孤立杂点
  → 人工定义前臂/手部切分区域
  → 修补底图上原有笑嘴
  → 主体、前臂分别描摹成 SVG 路径
  → 组装共享母版，添加四嘴型、眼皮和腕部旋转中心
  → 输入帧号，控制显示状态与旋转角度
  → 浏览器逐帧截图，合成 MP4 / GIF
```

关键是将“轮廓矢量化”和“动画语义”分开处理。VTracer 提取颜色和轮廓，不理解嘴巴、手臂、遮挡或骨骼；可控制的图层、嘴型和关节由人工规则构造。最终 SVG 没有嵌入 PNG，动画也无需反复生成不同人物图片。

本实验直接描摹原图，是为验证技术链路并保留人物特征。生产阶段可以用简化重绘减少路径；这不是本次已经完成的工作。

## 3. PNG 预处理与人工拆层

### 3.1 清理透明杂点

原图转为 RGBA 后，以 Alpha ≥ 128 创建二值掩码；从 `(600,1000)` 使用 flood fill 标记人物主体连通区域。随后用 `MaxFilter(5)` 做 5 × 5 膨胀，在主体周围保留约 2px 边缘，尽量保住抗锯齿像素。最终 Alpha 为原 Alpha 与该掩码的最小值。

这一步清掉与主体分离的黑点和噪声，可能同时移除不连通的细发或装饰，因此换图时必须重新检查。

### 3.2 从原图切出前臂和手

手部掩码由人工多边形定义，顶点依次为：

```text
(60,450), (280,450), (280,725), (215,770), (207,855),
(204,899), (173,912), (128,914), (90,901), (80,885),
(88,845), (105,790), (113,760), (92,715), (65,670)
```

多边形内部保留到前臂图层，主体图层对应区域透明，形成互补切口。袖口和躯干仍固定，切分终点位于袖口附近。这是针对当前图的手工语义切分，不是自动人体分割；也没有补画大幅摆臂后会露出的身体。

### 3.3 移除底图中的原笑嘴

底图上已有笑嘴，直接叠新嘴型会出现双嘴。脚本用中心 `(576,529)`、旋转 −16°、半轴 `(98,44)` 的局部椭圆建立修补区域：

- 周围采样条件为椭圆归一化半径 `1.05 < r < 1.38`、`y < 565`、`475 < x < 680`、`R > 220`、`G > 150`。
- 用最小二乘拟合 RGB 的局部线性肤色平面，特征为 `1`、`(x−576)/100`、`(y−529)/100`。
- 用 `clip((1−r)/0.15,0,1)` 混合修补结果和原底图，减弱边界突变。

完成后输出 `work/body.png` 和 `work/arm.png`。这是显式局部重建，不是自动理解或无损恢复原本被嘴巴遮住的皮肤。

## 4. VTracer 描摹和 SVG 组装

主体和前臂分别转换，使用完全一致的参数：

| 参数 | 值 |
| --- | --- |
| `colormode` | `color` |
| `hierarchical` | `stacked` |
| `mode` | `spline` |
| `filter_speckle` | `6` |
| `color_precision` | `7` |
| `layer_difference` | `8` |
| `corner_threshold` | `60` |
| `length_threshold` | `4.0` |
| `max_iterations` | `10` |
| `splice_threshold` | `45` |
| `path_precision` | `2` |

解析两个原始 SVG 的子元素后，合并到 `viewBox="0 0 1086 1448"` 的母版。母版按以下顺序绘制，后面的覆盖前面的：

```text
body：固定主体路径
pointing-arm：原指向前臂路径，data-pivot="147 894"
eyelids：默认隐藏的肤色椭圆和闭眼曲线
mouth：translate(578 521) rotate(-16)
  mouth-closed / mouth-small / mouth-open / mouth-round
```

四种嘴型和两只眼睛的闭眼覆盖层由代码手绘，不是从 VTracer 自动提取。原眼睛仍在底图里；眼皮覆盖其可见区域来模拟闭眼。头部、头发、眼镜、衣服没有独立骨骼。

必须保留 SVG 默认命名空间。实现使用 `ET.register_namespace('', 'http://www.w3.org/2000/svg')`，避免生成 `ns0:path`。带前缀形式虽然可被 XML 解析，但这个页面通过 HTML `innerHTML` 内联时曾导致主体几何不显示，只有手绘覆盖层可见。修复后，根元素有 SVG `xmlns`，内部路径保持无前缀；导出脚本另用实际包围盒检查防止这种假成功。

当前最终统计来自 `build-info.json` 和独立验证报告：

| 项目 | 数值 |
| --- | --- |
| 主体描摹路径 | 1,726 |
| 前臂描摹路径 | 182 |
| 描摹路径合计 | 1,908 |
| 最终 SVG | 1,916 个 path、3 个 ellipse |
| 文件字节数 | 1,093,942，约 1.04 MiB |
| 位图与外部纹理 | 无 image 元素、嵌入位图或外部纹理引用 |

最终 path 比描摹路径多 8 条，因为增加了嘴型和眼皮曲线；ellipse 单独计数。

## 5. 帧控制接口与实际时间轴

时间轴固定为 30fps、240 帧（0–239），总长 8 秒。帧状态由帧号直接求得，避免逐帧累计变换造成漂移。预览时钟只是不断请求帧号；离线截图直接指定目标帧。

| 接口或元素 | 用途 |
| --- | --- |
| `window.svgHostReady === true` | SVG 已加载并完成初始应用 |
| `window.pauseAnimation()` | 停止预览时钟 |
| `window.setFrame(value)` | 向下取整后按 240 正向取模，应用当前帧并返回状态 |
| `window.currentFrameState` | `{frame, mouth, blink, arm}` |
| `#stage` | 浏览器截图区域 |

`setFrame()` 会受到页面手动选择器覆盖。自动导出使用新页面，选择器默认均为 `auto`；手动操作后若要复现自动时间轴，须把嘴型、眼睛、手臂选择器都恢复为自动。“对比原位”按钮会设为手动闭嘴、睁眼、0°。

设 `t = frame / 30`，自动规则如下：

| 动作 | 精确规则 |
| --- | --- |
| 模拟说话窗口 | `0.7 < t < 3.25` 或 `4 < t < 7.1`，其余闭嘴 |
| 嘴型选择 | `sequence[floor(t*7) % 8]`，序列为 `small, open, small, closed, round, small, open, closed` |
| 眨眼 | 起始帧 48、115、192、222，各连续 4 帧，即 48–51、115–118、192–195、222–225 |
| 第一段腕部摆动 | 1.2–3.5 秒：`−4*sin(π*(t−1.2)/2.3)` 度 |
| 第二段腕部摆动 | `4.4 < t < 6.4`：`3*sin(π*(t−4.4)/2)` 度 |
| 其他腕部状态 | 0°；旋转中心始终 `(147,894)`，角度写入时保留 4 位小数 |

任一帧恰好显示一个嘴型；眼皮按 blink 显隐；手臂通过 SVG `rotate(angle 147 894)` 控制。所有底图路径共享，只有局部图层状态变化。当前节奏完全由预设时间轴产生，没有音频输入或唇形同步。

页面还支持暂停、重播、拖动时间轴、手动选择状态，以及把当前内联 SVG 序列化下载。下载的是当前帧静态 SVG，不包含 HTML 中的动画控制程序。

## 6. 从仓库复现

### 6.1 构建母版

前置条件：Python 3、可用的 pip 和原始 PNG。以下命令均在仓库根目录执行；版本来自现有实验 README 和已安装环境记录。

```sh
python3 -m venv /tmp/svg-host-venv
/tmp/svg-host-venv/bin/pip install vtracer==0.6.15 pillow==13.0.0 numpy==2.5.4
/tmp/svg-host-venv/bin/python experiments/svg-host-poc/build.py
```

脚本会写入或覆盖实验目录内 `source.png`、`character.svg`、`build-info.json`，以及 `work/` 中间文件。构建后核对尺寸、路径数和文件大小；不同依赖/平台变动不能仅凭执行成功就假定逐字节相同。

### 6.2 预览和手动检查

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

浏览器打开 [本地实验预览](http://127.0.0.1:8765/experiments/svg-host-poc/)。该链接仅在本地服务运行时有效；端口可按需要修改。

检查左右人物是否完整显示，再分别查看四种嘴型、闭眼和手部角度。关注嘴部修补边缘、眼镜附近眼皮遮挡、腕部切口和发丝轮廓。页面显示“路径数”并不保证主体真的渲染，仍要观察人物及实际几何。

### 6.3 导出样片与自动检查

前置条件：Node.js、可加载的 `playwright-core` 模块、与之适配的 Chromium/Chrome 可执行文件，及 PATH 中的 `ffmpeg`。

`render-check.mjs` 当前默认 Playwright 模块和 Chrome 路径属于原验证机器 `/Users/ljk/...`。其他机器应传入环境变量，不要把默认路径当成通用安装位置。下面两项路径是占位示例，执行前替换为本机真实路径：

```sh
PLAYWRIGHT_MODULE='/absolute/path/to/node_modules/playwright-core' \
CHROME_PATH='/absolute/path/to/chrome-executable' \
node experiments/svg-host-poc/render-check.mjs
```

在原验证机器默认路径仍存在时，也可直接运行：

```sh
node experiments/svg-host-poc/render-check.mjs
```

脚本自行在 `127.0.0.1` 选择临时端口提供文件，不需要先启动预览服务。它以 1440 × 1100、设备像素比 1 的页面加载实验，等待 ready，暂停动画后执行：

1. 检查 `body` 路径至少 900 条，实际包围盒宽至少 1000、高至少 1300，以发现主体缺失。
2. 保存全页面 `preview.png`。
3. 捕获第 43 帧，跳到 130，再返回 43，比较两次截图字节。
4. 对帧 0–239 调用 `setFrame()`，逐帧截图 `#stage`，保存 `frames/0000.png` 等文件。
5. 检查浏览器 `pageerror`；通过后调用 FFmpeg 输出 MP4 和 GIF。
6. 写入 `render-evidence.json`。

MP4 使用 30fps、libx264、yuv420p、CRF 18，并将画面补齐至偶数宽高；GIF 从 MP4 转换为 12fps、宽 640px、循环播放。GIF 帧率与母版 30fps 不同，不能据此检查每一个源帧。

默认捕获 `#stage`，可用 `STAGE_SELECTOR` 覆盖；改变捕获区会改变输出尺寸和画面。输出位于 `out/svg-host-poc/`，会覆盖同名结果；默认画面包含实验舞台背景，不是透明视频，也不是 1920 × 1080 的生产合成。

## 7. 已有验证证据与可作出的结论

依据 `experiments/svg-host-poc/VERIFICATION.md` 记录的独立审核：

- 最终 SVG 结构检查通过：1,916 个 path、3 个 ellipse，无嵌入位图、外部图像或纹理引用。
- 浏览器主体渲染检查得到 1,726 条主体路径，包围盒约 1068.49 × 1409.64。
- 完成 240 帧、30fps、8 秒导出，没有记录到浏览器页面错误。
- 第 43 帧在跳转到第 130 帧后重新捕获，与此前截图字节一致。
- 抽查对比预览、帧 49 和帧 70：人物完整，头发、眼镜、胡须、衣服和原指向姿态保留；可观察到嘴型与闭眼变化，抽样未见明显腕部缺口，原分离黑点已消失。

可作出的结论是：**现有详细 PNG 可以转换为真实路径，再添加人工构造的语义控制图层，实现按帧局部动画与视频导出。**

验证没有覆盖每帧视觉审查，也没有对所有帧做重复捕获；单个重复帧结果不能扩大为全系统、跨机器的像素确定性保证。本次文档补录没有重新生成样片。

## 8. 限制和后续边界

| 限制 | 实际影响 |
| --- | --- |
| 渐变量化与大量路径 | 会损失细发/阴影细节；约 1.04 MiB 的母版尚未做生产级简化 |
| 坐标和切分手工定义 | 换人物不能直接复用，需要重新定位并视觉核对 |
| 眼皮是覆盖层 | 原眼睛留在底图；局部风格和遮挡仍需精修 |
| 嘴部为肤色重建加手绘状态 | 不是从原图自动得到完整口腔或真实发音模型 |
| 腕部只有 −4° 至 +3° 的轻微动作 | 不能推导大幅摆臂可用，也没有摊手等替代手势 |
| 无头身独立拆层或完整骨骼 | 目前不能支持完整转头、行走或复杂肢体动作 |
| 嘴型时间轴为模拟序列 | 没有语音、音素、TTS 或真实唇形同步 |
| 独立浏览器导出 | 没有修改现有主持人组件，也没有完成生产 Remotion 集成 |
| 截图和视频为被忽略的生成物 | 长期保存须依赖原图、脚本、母版和元数据，而非只保留输出路径 |

后续可以在独立变更中精修母版、补画遮挡区域与替代手势，再接入外部帧状态时间轴。语音同步和完整骨骼应分别定义验收，不能视为当前 POC 已证明的能力。
