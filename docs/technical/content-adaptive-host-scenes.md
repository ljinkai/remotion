# 内容驱动的数字人解释镜头

本文件是 `openspec/changes/improve-content-adaptive-host-scenes/` 的独立技术备份。

## 目标与边界

中间区域根据每次案例的讲解组织流程、图片和解释卡片，减少小段引用下方的大块留白。素材必须来自当前案例；数字图表继续遵守已有证据校验，图片保留来源，演示性质的画面不能冒充真实产品截图。

人物在所有镜头使用相同的 560×747 尺寸和右下角位置（right -16、bottom -36）；允许遮挡下方图层。字幕继续使用上移的黄色描边样式和两行分页。

## 数据流

1. Markdown 与逐字稿生成原始分镜，或恢复已有分镜缓存。
2. 共用增强入口清理不受来源支持的数据，保留原图与已验证图表。
3. 对适合解释的文字内容，根据原句和同案例上下文生成 `explanation` 元素。
4. 前端按 `layout` 组织中间舞台，逐帧确定性地展示节点或卡片。
5. Workbench 预览与 MP4 导出读取同样的增强结果，不改写讲解文本、音轨和时间。

## 元素约定

```ts
{
  type: 'explanation',
  layout: 'flow' | 'features' | 'contrast' | 'spotlight',
  title: string,
  items: { label: string; detail?: string }[]
}
```

- flow：原文有明确顺序或方向，显示连接节点与当前步骤。
- features：并列能力或要点，使用同等视觉权重的卡片，不画因果箭头。
- contrast：原文明确对照，使用两侧内容比较，不推导数值差距。
- spotlight：信息不足时突出真实观点，使用原句分块，不补造特征。

布局选择不能硬编码为某一期或某一个产品。无有效依据时退回可读的原文呈现；原图无法访问时保留已有缺图回退，不降低 HTTPS 校验。

## 兼容与验证

- 已有 `statement` 标记不阻止重新选择解释版式。
- 已核对图表和关系镜头优先，解释增强不得覆盖其数值、单位、来源。
- 二次增强应保持稳定，不重复追加元素或混入其他案例上下文。
- 回归测试覆盖不同案例类型、无依据方向、无依据数字、图片保留、长英文和不变的原始输入。
- 实际渲染检查长接入讲解、并列功能、明确流程、对比和单观点；Workbench 小窗口检查完整竖屏与黄色字幕。
