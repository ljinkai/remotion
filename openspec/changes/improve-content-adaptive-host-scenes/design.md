## Context

已有分镜缓存使用 statement 等场景标记。仅修改规划提示无法改善已有内容；需要在生成、缓存恢复、预览与导出共用的增强入口补充可追溯的展示数据。

## Decisions

- 使用 explanation 元素承载 layout、title 和 items（label、可选 detail），保持旧场景枚举兼容。已有真实 chart/relationship 优先。
- flow 必须有来源支持的方向或顺序；features 用于并列能力；contrast 必须有明确对照语义；证据不足使用 spotlight。不得把任意列表画成因果链。
- 原句、同案例相邻讲解和案例正文提供依据；不能跨案例借用功能、数据或图片。
- 来源图继续显示，解释卡片不冒充产品真实界面；无图场景用有意义的排版填充中部，避免无关装饰。
- 渲染只依赖分镜与当前帧，支持确定性寻帧。长内容使用可读分块或渐进显示，不能在关键英文术语中间截断。
- 主持人固定 560×747，right -16、bottom -36；黄色字幕维持既有分页与位置，允许覆盖下方图层。

## Risks / Trade-offs

- 规则提取可能无法理解复杂语义：采用保守 spotlight 回退，宁可保留原句也不补造功能。
- 原图服务器不可用：继续使用现有缺图回退，不关闭 HTTPS 校验。
- 更多镜头并非自动保证解释准确：增加异质案例与反例测试，并检查实际渲染。
