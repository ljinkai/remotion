# 数字人中间内容区设计

## Context

这是用户已明确批准的既有分镜工作流改进。目标是让画面解释旁白，并让文中已有图片进入最终视频。保持一行旁白对应一条分镜、共用 SVG 主持人、沿用语音时间轴。

## Decisions

1. `HostBeat.scene` 为可选的 `product | metric | steps | statement`，已有 `elements` 继续承载实际内容和图片；旧数据按元素与上下文推断场景。
2. 产品实景用大图、边框和简短说明；核心数字突出原始单位与上下文；步骤流程使用原文已有的动作和短语；观点强调用有层次的排版。取消中间区域强制等分和大卡片填满。
3. 图片来源沿用当前案例素材白名单。有图片的案例首条分镜应展示该图，不以“截图”等关键词为前提。有效图片在其他场景可以作为辅助内容保留，不能被四元素截断静默丢弃。
4. 镜头只改变构图和注意力，不编造事实。单个金额不能推导增长曲线，原文没有的功能不能作为步骤。信息不足时降级为观点强调。
5. 动作由 Remotion 帧号直接计算，先建立、再强调、最后停留；图像完整展示优先，不能为了铺满而裁掉产品内容。错误图片显示说明卡，不让整个视频渲染失败。
6. 已缓存分镜在进入 Workbench 的共享预览/导出 props 前整理，保留原稿件、语音和时间数据，避免仅更新新生成分镜。

## Verification

- 单测覆盖图片补全和保留、非法来源、场景推断、无事实支撑的图表回退、旧缓存兼容和时序不变。
- TypeScript、改动文件检查和严格 OpenSpec 校验。
- 通过实际 Workbench 内容预览四类镜头，抽查图片完整性、手机端文字尺寸、主持人/字幕遮挡，并实际导出视频检查。
- 本次视觉验收为关键帧抽查，不能扩大为所有图片、所有输入和全帧质量保证。

## Risks / Trade-offs

- 网页截图比例差异较大：以 contain 和自适应留白优先，提供图片失败回退。
- 原文没有真实步骤或数值：保守降级，不添加填充信息。
- 自动布局仍需后续样片迭代，本变更不承诺通用生成任意风格画面。
