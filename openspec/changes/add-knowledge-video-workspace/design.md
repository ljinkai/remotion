## Context

现有视频引擎具备来源支持的解释元素、主持人和语音时间轴，但业务模型、缓存和画幅与周刊绑定。本次把知识创作交互独立出来，继续复用底层渲染能力。

## Decisions

- `/knowledge` 使用独立 React entry 与样式、独立缓存 key；`/` 保持周刊。
- 文档保存原始 source 和可编辑章节 narration，不要求每个二级标题只有一段短稿。
- 离线提取只整理结构并保留原文，不冒充 AI 提炼；AI 润色使用独立提示，明确保留数据限定、出处和观点分界，只有显式操作才调用。
- 文档转换成共享 beat/cue 数据便于复用配音；内部兼容字段不是面向用户的“案例”。不套入固定周刊 intro/closing。
- 新 `KnowledgeExplainer` composition 固定 1920×1080，包含主题、章节进度、解释主舞台、右下固定人物和上移黄字幕。
- 数据变化使下游结果失效；请求发出时保存输入快照，旧响应和错误不得改变新文档。音色变化清除旧音轨。
- 计划、预览和导出读取同一 props，导出按知识模式选择横屏 composition，不能仅改预览尺寸。

## Risks / Trade-offs

- 原始长资料不一定是优质讲稿：离线草稿明确标识，允许编辑，AI 仅辅助。
- 知识判断与医学案例应保留来源、限定与类比说明，不能从小鼠初步结果推导人体疗效。
- 此次本地专用工作区不扩展为多租户 SaaS，也不引入自动录屏或精确口型。
